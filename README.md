# above-ground
A mental health app to help you stay above ground. Helps with anxiety, depression, grounding exercises, and more.

## Structure
One codebase runs as the website (https://aboveground.app) and as the iOS and Android apps (Capacitor).
- `index.html`, `src/` — the app. `src/platform.js` holds everything that differs between web and native.
- `public/` — copied as-is into the build: web manifest, icon, service worker (web only), `version.json`.
- `ios/`, `android/` — native projects generated by Capacitor (app ID `app.aboveground`). Committed.
- `assets/` — source images for the native app icons and splash screens (`npm run assets` regenerates them).
- `supabase/migrations/` — database schema and functions for Supabase project `ahamlyfqmwfpggntigjy`.

## Building
Requires Node 22.
- `npm run dev` — local dev server.
- `npm run build` — builds the website into `dist/` (what Netlify runs).
- `npm run native` — builds, copies the version into the native projects and runs `cap sync`.
- `npm run ios` / `npm run android` — the same, then opens Xcode / Android Studio.

GitHub Actions (`.github/workflows/native-build.yml`) builds the Android and iOS apps on every push and
pull request and attaches an installable Android debug APK and an iOS Simulator build to each run.

## Native extras
- Deep links `aboveground://start?feeling=anxiety|depression|grounding` and `aboveground://help` (website: `?start=…`, `?help`).
  Widgets, Siri Shortcuts and Android shortcuts all use them; `src/platform.js` → `onDeepLink`.
- iOS: `ios/App/AboveGroundWidget/` (WidgetKit extension, bundle `app.aboveground.widget`), `App/AppShortcuts.swift`
  (App Intents), `App/HealthPlugin.swift` (Apple Health, registered in `App/MainViewController.swift`).
- Android: `FeelingsWidget.java` + `res/layout/feelings_widget.xml`, `res/xml/shortcuts.xml` (launcher shortcuts and
  App Actions), `HealthPlugin.java` (Health Connect, Android 16+, registered in `MainActivity.java`).

## Previewing changes before they go live
Changes go through pull requests. Each pull request gets a comment (updated on every push) with:
- **Website:** the Netlify deploy preview, `https://deploy-preview-<N>--above-ground.netlify.app` (Netlify sign-in).
- **Android:** a direct APK download and QR code (prerelease `pr-<N>`); open it on a phone to install.
- **iPhone:** `npm run preview:ios -- <N>` on a Mac installs and opens that build in the iPhone Simulator
  (needs Xcode and the GitHub CLI, `brew install gh && gh auth login`).

Every push to `main` publishes the same as prerelease `dev`: the latest development build
(`npm run preview:ios` with no number opens it). Preview prereleases are removed when their pull request closes.
Once the store accounts exist, releases will also go to TestFlight and Google Play internal testing.

## Storage
On the web, settings, cached content and the event queue live in localStorage, and Supabase keeps its
anonymous sign-in there too. In the native apps localStorage is only a cache: every value is mirrored to
Capacitor Preferences and restored at launch, and the Supabase session is stored in Preferences directly.

## Content
All content — exercises, affirmations, completion messages and welcome greetings — lives only in Supabase.
The app ships none of its own; it keeps a copy of the last content it loaded so it keeps working offline.
To add or change content, edit the rows in Supabase (set `is_active` false to retire one).

## Other content tables
- `crisis_resources` — the lines shown by "Need more help?", one or more per country (ISO code, e.g. `US`), plus a
  `*` row used for any other country. `phone`/`sms` are dialable numbers; `emergency` is the local emergency number.
- `reminder_messages` — wording for the gentle reminder notifications (apps only); one is picked at random.
- On `exercises`: `research_summary` and `sources` (`[{title, year, url}]`) power "Why this works"; `audio_url` adds a
  recorded guide; `body.pacing` (`{phases: [{label, seconds, motion: in|hold|out}]}`) adds the breathing guide.

## How content is picked
Exercises and affirmations come from the `pick_content` database function. It weights choices using
only the current device's history: unseen ×3, up-voted ×2.5, down-voted ×0.2, and items shuffled often
relative to views are picked less. The app falls back to a plain random pick when offline.

## Versioning
Versions follow [Semantic Versioning](https://semver.org/) and live in `package.json`. To release:
1. Bump the version: `npm version patch|minor|major --no-git-tag-version` (or edit `package.json`).
2. Add an entry to `CHANGELOG.md`, commit, and push to `main`.

On each deploy Netlify runs `npm run build`, which writes `public/version.json` (version, release time, commit),
gives the service worker a per-release cache name, then builds with Vite. `npm run native` also writes the version
into the iOS and Android projects (build number = major×10000 + minor×100 + patch, e.g. 1.3.0 → 10300). Settings → Last Updated shows that release time.

## Device names
Each device (an anonymous Supabase user) gets a permanent name such as "Kind Cookie Pony", assigned by the
database on first sign-in (`devices.name`). The optional `devices.nickname` is for an admin-set label.
